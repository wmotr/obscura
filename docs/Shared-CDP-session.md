# Share one CDP session across clients

Normally each CDP connection gets its own pages, DOM and cookie jar.
`obscura serve --shared-session` instead lets authenticated clients coordinate
on one browser session. This supports the browser-harness/vault-supervisor
pattern used by Hermes: both clients must inspect and fill the same document.
It does not add a credential vault to Obscura.

## Start a session

Run one server process per task. Create a random token in a private file;
never pass the token itself as a command-line argument:

```bash
mkdir -p ~/.config/obscura
# Refuse to overwrite an existing file. Generate 256 bits in URL-safe hex.
(umask 077; set -C; python3 -c 'import secrets; print(secrets.token_hex(32))' > ~/.config/obscura/session-token)

obscura serve --shared-session \
  --session-token-file ~/.config/obscura/session-token --port 9222
```

The file must contain 32-4096 characters from `[A-Za-z0-9._~-]`, optionally
followed by a newline. On Unix, group/other permissions must be zero (`0600`
or stricter). Length is checked, not randomness: use a generated token, not a
memorable password. Use a fresh token and port for each independent task.

The server logs its address and token-file path, never the token. It refuses
non-loopback bind addresses, `--workers` greater than one and `--storage-dir`.
Cookies remain in memory and disappear when the server stops.

## Connect Hermes or another CDP client

Clients can authenticate with `Authorization: Bearer <token>` during the
WebSocket upgrade, or with `?token=<token>` on the endpoint. For Hermes,
configure its external CDP endpoint, for example in a trusted shell with shell
tracing disabled:

```bash
set +x
TOKEN="$(cat ~/.config/obscura/session-token)"
export BROWSER_CDP_URL="ws://127.0.0.1:9222/devtools/browser?token=${TOKEN}"
unset TOKEN
hermes
unset BROWSER_CDP_URL
```

Do not paste the expanded URL into a conversation, command arguments or logs.
The endpoint token grants full control over this browser session. Prefer an
authorization header where the client supports it, and do not expose the
endpoint through a proxy. Local programs running as your user can read the
file/environment; this is not a sandbox against those programs.

Hermes continues to own its vault, resolve credentials, check the exact site
origin and redact model-facing results. Obscura accepts normal CDP commands;
it does not know which values are credentials. A successful CDP connection
alone is not proof of end-to-end Hermes vault compatibility.

## Session behavior

- One server process owns one shared session. All clients with its token are
  mutually trusted, not separate tenants.
- Pages, JavaScript, cookies, localStorage and sessionStorage are shared.
  A page survives client disconnects and reconnects while the server runs.
- Command responses go only to their requester. Different clients can reuse
  command IDs without receiving each other's responses.
- Events are broadcast to attached clients, including console, network and
  interception events. Flattened target-session IDs remain those generated by
  Obscura; clients must tolerate events for other attachments. All authorized
  clients can inspect the shared page or resolve intercepted requests.
- `Browser.close` disconnects its requester without terminating the other
  clients' browser. Stop the server process to destroy the shared session.
- A bounded outbound queue and write timeout disconnect slow readers. The
  CLI limit is 16 attached clients; `--max-connections` only controls the
  default isolated mode. Command queues are also bounded.
  Incoming commands are limited to 1 MiB. Outgoing messages are limited to
  8 MiB and each client's queued output to 16 MiB. Exceeding these limits
  disconnects that client, including for oversized screenshot responses.
- Servers without `--shared-session` retain per-connection isolation.

## Security boundaries

Discovery (`/json`, `/json/list`, `/json/version`, `/json/protocol`) requires
authentication and is not cached. Returned WebSocket URLs contain the token:
treat discovery responses as secrets too. `/json/list` is a bootstrap entry
for `page-1`, not a live tab inventory; use CDP `Target.getTargets` for current
pages and URLs. WebSocket paths are limited to
`/devtools/browser` and `/devtools/page/*`. WebSocket requests with an `Origin`
header are rejected to block drive-by connections from browser pages.

CDP frame contents are not echoed in parse-error warnings. This is not general
redaction of application data: pages, console/network events, error messages,
URLs and observability instrumentation can contain sensitive data. Keep
telemetry disabled for secret-bearing workflows unless the entire output path
has been audited. Route all model-facing browser reads through Hermes's
redaction boundary; a parallel unrestricted MCP/CDP tool can bypass it.

As with Chromium, once a password is filled, the destination page and its
scripts can read it. Origin checks prevent filling on the wrong site, not
exfiltration by a compromised authorized site. Never attach mutually
untrusted clients or use a real vault to validate this integration initially.
